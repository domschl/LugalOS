# LugalOS Tokenized Kernel Logging Macro System

LugalOS implements a high-efficiency **tokenized dictionary logging subsystem** (`kernel/printk.c`, `kernel/klog.c`, `kernel/klogd.c`). Inspired by dictionary logging in systems like Zephyr, LugalOS achieves nearly **6× compression** in ring buffer storage without requiring host-side decoding tools.

---

## 1. Motivation: The Memory Waste of Text Logging

In an embedded operating system, diagnostic log messages generated by drivers and microkernel subsystems are invaluable. However, traditional text logging wastes substantial SRAM:
* A typical boot generates ~2,645 bytes of log messages.
* Analysis shows that **89% of those bytes are literal strings** (such as `"[klogd] Log consumer running as task #%d..."`).
* In an 8 KB circular ring buffer, traditional text logging can only retain 3 complete boots before overwriting old messages.

---

## 2. Architectural Design: In-Kernel Tokenized Records

Instead of copying rendered text into the circular log ring, LugalOS captures the message structure:

```
Traditional Text Logging (Wasteful):
  "[    0.012] [palloc] Initialized 8192 pages (32768 KB) free\n"  --> 60 bytes stored in RAM

LugalOS Tokenized Logging (Compact):
  { uint16_t render_len }           (2 bytes)
  { const char *fmt }               (4 bytes: pointer to .rodata string)
  { uint32_t timestamp }            (4 bytes)
  { uint32_t arg1, uint32_t arg2 }  (8 bytes: captured argument blob)
  --> Total stored in RAM: 18 bytes (3.3× to 6× compression!)
```

### Key Properties
1. **Zero Call-Site Churn**:
   Developers write standard formatted logging calls:
   ```c
   printk("[net] Interface %s linked up at %d Mbps\n", ifname, speed);
   ```
2. **Flash `.rodata` Pointers as Unique Identifiers**:
   Because format strings reside permanently in Flash `.rodata`, their 32-bit (or 64-bit) memory addresses serve as immutable, unique dictionary IDs.
3. **In-Kernel Expansion at Drain (Zero Host Dependency)**:
   Unlike host-dependent dictionary loggers that require external ELF symbol tables to decode serial logs, LugalOS expands tokenized records **directly inside the kernel** when the log is drained:
   * When `cat /proc/kmsg` is executed, or when the background `klogd` flusher task writes to the console, the kernel reads the `.rodata` format string pointer, parses the captured argument blob, and renders the human-readable text on the fly.
   * `cat /proc/kmsg` remains fully readable over serial consoles, LCD screens, and Plan 9 network links.

---

## 3. Compiler Checking & Format String Safety

To ensure that argument blobs match format strings with byte precision:
* Functions are annotated with `__attribute__((format(printf, 1, 2)))` via `LUGALOS_PRINTF`:
  ```c
  int printk(const char *fmt, ...) LUGALOS_PRINTF(1, 2);
  int cprintf(const char *fmt, ...) LUGALOS_PRINTF(1, 2);
  int printk_critical(const char *fmt, ...) LUGALOS_PRINTF(1, 2);
  ```
* This turns format-width mismatches into compile-time errors, preventing binary argument corruption.

---

## 4. Asynchronous Consumer Task (`klogd`) & Output Sinks

* **Non-Blocking `printk()`**:
  `printk()` simply packages arguments, appends the record under a fast `spinlock_t`, and wakes `klogd`. It **never blocks**, making it safe to call from any context (including interrupt handlers and IPC callbacks).
* **Asynchronous `klogd` Flusher**:
  A dedicated background task (`klogd`, priority `TASK_PRIO_BACKGROUND`) drains the ring buffer and distributes rendered characters to registered sinks.
* **Pluggable Output Sinks**:
  * `"console"`: Streams to UART0 / USB-Serial.
  * `"lcd"`: Streams to the active LCD terminal emulator.
  * Sinks can be detached at runtime (`klog detach console`) so background logs do not interrupt interactive shell typing.
