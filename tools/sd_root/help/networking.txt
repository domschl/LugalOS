============================================
LUGALOS PLAN 9 NETWORKING & HOST INTEGRATION
============================================

LugalOS implements native Plan 9 file protocol (9P2000) services and an
embedded IPv4 network stack. This enables bidirectional filesystem sharing,
live MicroSD card synchronization without removing physical media, and network
appliance operation.

------------------------------------------------------------------------------

1. MICROSD SYNCHRONIZATION VIA 9P (TOOLS/P9SYNC.PY)
---------------------------------------------------

tools/p9sync.py synchronizes local host directories directly with the board's
/sd0 MicroSD card over serial links without interrupting running tasks:

[Synchronizing RP2350 Hardware]

On RP2350 devices, 9P runs over the secondary USB CDC interface (if02):

    uv run --project host/p9lib python3 tools/p9sync.py \
        --serial /dev/serial/by-id/usb-LugalOS_*_Dual_CDC_ACM_*-if02 \
        --src build/rp2350-terminal/sd_root \
        --dst /sd0

[Synchronizing ESP32-P4 Boards]

On ESP32-P4 boards (which have a single console port), p9sync.py uses p9share
to multiplex 9P over the console UART using SLIP framing:

    python3 tools/p9sync.py --p4 lcd7b --src build/esp32p4-lcd7b/sd_root

[Preservation Policy]

tools/p9sync.py is strictly additive and idempotent:
  * Creates missing directories on the board (e.g. /sd0/cas/, /sd0/help/).
  * Updates files that differ in size or timestamp.
  * Preserves user data: Never overwrites existing user games
    (/sd0/CHESS/) or history files.

------------------------------------------------------------------------------

2. MOUNTING LUGALOS ON LINUX VIA FUSE-P9
----------------------------------------

The host/fuse-p9 utility mounts a running LugalOS filesystem directly into the
Linux host directory tree:

    # Mount LugalOS over TCP (e.g. Wi-Fi node)
    mkdir -p /mnt/lugalos
    ./host/fuse-p9/fuse-p9 -s 192.168.1.50:564 /mnt/lugalos

    # Files on the microcontroller are now accessible on the host:
    ls -la /mnt/lugalos/sd0

3. NETWORK INTERFACES & WI-FI CONFIGURATION
-------------------------------------------

[Querying Network State]

From the LugalOS shell:
    lsh> net
    Interfaces:
      eth0: MAC 02:4c:75:67:01:00, Link UP, 100 Mbps Full-Duplex
      rx: 1420 frames, tx: 850 frames

[Joining a Wi-Fi Network]

For wireless presets (rp2350-wifi, esp32c6):
 1. Derive the 64-character hex WPA2 PSK on the host:
       wpa_passphrase "MySSID" "MyPassword"
 2. Join the network from the board:
       lsh> wifi join MySSID <64-char-hex-psk>
 3. Assign a static IP address or let the supervisor auto-configure:
       lsh> netcfg 192.168.1.50 255.255.255.0 192.168.1.1
 4. Start the 9P TCP file server:
       lsh> net listen 564

4. WI-FI THROUGH THE BOARD'S ESP32-C6 (ESP32-P4 BOARDS)
-------------------------------------------------------

The ESP32-P4 boards (esp32p4, esp32p4-lcd7b) have an ESP32-C6 beside the P4,
wired to it over SDIO. Running LugalOS on both (esp32c6-mini on the C6), the
C6 is the P4's network card: the LugalOS Link Protocol [1] carries Ethernet
frames and 9P between them, and the P4 gets wlan0 with the C6's station MAC.

  * At boot the C6 (esp32c6-mini) arms the radio role and waits for a
host, and an LCD-7B (whose only network is its C6) starts the host role. On
the NANO, which has Ethernet as well, type llp host on the P4. By hand on
either side: llp radio (C6), llp host (P4).
  * Link up (within a second of both running): the P4 registers wlan0
with the C6's station MAC and asks for a DHCP lease once the radio is
associated. The C6 gives its interface to the link only now. A C6 with no host
stays a node of its own, with its own IP.
  * /c6. At every link-up the P4 mounts the C6's namespace at /c6, afresh
after a C6 restart (9P over the same channel, no authentication: it is a
cable). cat /c6/proc/version, cat /c6/proc/node.
  * Credentials stay on the P4. Store them once on the P4 with
wlan SSID PSKHEX (the derived 64-hex key, see above). At each link-up, while
the radio is not associated, the P4 writes join SSID PSKHEX to /c6/dev/wlan.
The C6 holds the key in RAM only, and reading /c6/dev/wlan says idle,
starting, not joined or joined.

Checks of the channel itself:

  Command | Where | What it does
  --------------------------------------------------------------------------
  llp | either | role, link state, peer, counters, SDIO channel state
  llp loop on / llp loop off | C6 | send the host's Ethernet frames back instead of to the radio
  llp bench [count] [size] | P4 | count frames of size bytes (default 1000 × 1514) to a C6 in loop mode, each checked on return; prints KB/s each way
  sdio | C6 | the SDIO slave: generation, timing, receive buffers, packets in and out
  sdio timing 0..3 | C6 | the slave's edges (0: send and sample on the rising edge)
  sdio, sdio probe, sdio reset | P4 | the host side; sdio reset pulses the C6's CHIP_PU

Measured on the LCD-7B at 20 MHz, 4-bit: 3.1 MB/s each way with 1514-byte
frames, nothing lost or damaged.
